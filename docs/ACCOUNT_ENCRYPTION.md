# 账号同步与加密存储

账号在客户端生成账号密钥，密码解锁后可在另一台设备恢复工作台配对和即时消息。云端保存加密后的私钥包、工作台配对记录、消息正文和附件。工作台仍通过已有 Noise 通道访问电脑；电脑需要在线，账号同步不把桌面执行迁到云端。

## 使用流程

1. 注册时设置密码，并保存客户端生成的恢复码。恢复码不会以原文提交服务器。
2. 在工作台点击“扫码添加电脑”，扫描电脑 `npm run pair` 显示的二维码。也可识别二维码图片或粘贴配对链接。客户端检查服务来源和电脑身份，不跳转到二维码里的任意网站。
3. 在另一台设备登录同一账号，客户端恢复配对记录，无需再次使用一次性配对码。现有浏览器的未归属配对在首次绑定账号时认领一次，之后与其他账号隔离。
4. 忘记密码时用 UID/用户名与恢复码登录，再设置新密码并保存新恢复码。修改密码保留账号密钥及历史，替换密码包装和恢复包装，撤销其他账号登录会话。

相机与浏览器密码学需要 HTTPS（本机 localhost 测试例外）。拒绝相机授权时仍可识别图片。相机在关闭、离开页面或页面进入后台时释放。

## 云端与客户端各保存什么

| 数据                                                                    | 云端               | 解密端                       |
| ----------------------------------------------------------------------- | ------------------ | ---------------------------- |
| 账号私钥、工作台配对身份和路由票据                                      | AES-GCM 密文       | 账号拥有者的已解锁客户端     |
| 即时消息正文、问题/授权详情与回复                                       | 签名的加密信封     | 发送时列入接收方的会话参与者 |
| 附件原文、文件名和类型                                                  | 文件密文与加密描述 | 获得文件密钥的参与者         |
| 用户名、公开昵称/头像、联系人关系、群成员/群名、消息顺序/状态/时间/大小 | 业务元数据         | 服务端可见                   |

“只有账号拥有者解密”适用于账号私有配置。聊天还必须授权通信对象，否则对方无法收信。服务器和对象存储没有账号根密钥或聊天私钥。内容搜索在客户端解密后分页执行，不将搜索词发送服务器。

## 密钥与消息格式

- PBKDF2-HMAC-SHA-256（600,000 次、随机 32 字节盐）在客户端派生密码材料，再通过不同 HKDF 上下文分出登录证明与包装密钥。服务器对登录证明进行带盐 scrypt 验证，原始密码不进入新账号接口。
- 随机 256 位账号根密钥由密码包装和随机 256 位恢复码分别保护。根密钥加密私钥包；私有配置使用 HKDF 子密钥和账号/记录 ID 绑定的 AES-256-GCM AAD。
- 聊天使用每次加密新生成的 P-256 ECDH 临时密钥和随机 AES-256-GCM 内容密钥，分别为参与账号包装内容密钥。账号 ECDSA P-256 签名覆盖上下文、接收方和全部密文。客户端验证发送者、会话、请求 ID、版本和签名。
- 授权回复另行签名并绑定会话、消息和交互 ID。只有指定回答者的有效签名才构成有效回复；云端单独改写 `approved` 不会得到有效授权卡片。
- 客户端固定首次获得的联系人公钥，并将固定结果加密同步。聊天顶部安全码可经可信渠道核对，防止首次公钥被替换。公钥变更不会自动接受。
- 群聊逐消息向当前账号成员包装密钥；移出的成员不获得后续密钥，新成员不能自动解密加入前的历史。同一账号的新设备恢复相同身份，可以解密该账号过去收到的消息。
- 幂等发送保留加密的初始请求，使用请求 ID 查询结果；服务端比较带密钥的操作标识，允许相同明文的加密重试，拒绝改变初始请求。流式内容共用原消息并递增版本。

这是基于 Web Crypto 原语实现的应用协议，不是 Signal、Matrix 或 MLS 兼容实现，也没有经过独立密码学审计。不提供双棘轮的前向保密或入侵后恢复：账号私钥泄露可影响已存历史。客户端、浏览器、Agent 运行环境和前端发布链是可信边界；恶意发布的 JavaScript 可以窃取客户端可用的密钥。弱密码仍可能遭离线猜测，应使用密码管理器生成的强密码。

## 工作台同步与撤销

配对记录逐条加密保存并进行版本比较。未完成云同步以本地密文待发送记录保留，联网后重试；读取云端快照前先提交待发送修改。后端区分各浏览器的设备会话，但这些浏览器代表同一账号授权的配对身份。

退出账号会断开当前工作台连接并移除本地解锁密钥。账号会话撤销不等于销毁已经下载的配对私钥：要撤销某电脑的账号级访问，应在设备管理解除配对，其他设备的同一配对也失效。密钥被盗时仅改密码不能收回攻击者已有密钥。

## Agent 接入

使用最新版 `npm run im -- register ...`。CLI 在本地生成密钥，通过注册请求提交公钥和加密私钥包，将令牌与解密私钥保存在 `0600` 状态文件。`src/client/encrypted-messaging.ts` 是浏览器和 Node 共用客户端；不要自行 POST 明文 `text` 或原始文件。使用 `incomingContent` 桥接附件时传入 `download: client.download.bind(client)`，先验证并解密，再交给 Agent。

Agent 与个人账号使用同一套加密模型。重置登录令牌不会更换身份或恢复丢失的私钥。

## 一次性迁移

正式服务只接受加密账号、消息和附件，没有明文兼容开关、明文登录/注册接口或账号内升级分支。启动时发现未转换的数据会拒绝启动，并保持原数据不变。

已有账号、UID、联系人、群、消息顺序、正文、回复、授权结果和附件通过独立的 [一次性迁移工具](ACCOUNT_MIGRATION.md) 保留。账号拥有者在自己的设备生成密钥并加密各自的数据；中继只接收公钥、加密账号包和签名密文。所有账号的迁移包验证通过后，统一切换数据库并清理被替换的媒体对象。正常客户端只读取一种密文格式。

## 验证

`test/account-encryption.test.ts` 验证跨设备解锁、密码/恢复码轮换、账号隔离、版本冲突、密文数据库检查、消息和附件解密、附件身份绑定、授权签名、重试及二维码来源检查。`test/account-workspace.test.ts` 使用实际 Noise/WSS 中继和模拟桌面，验证第二个账号会话仅凭密码和云端密文恢复配对并访问 Codex。它不替代真实手机摄像头验收或独立安全审计。

密码派生参数参考 [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)；密码学原语使用 [W3C Web Cryptography API](https://www.w3.org/TR/webcrypto/)。
