## 自动化与实际流量证据

- `npm run typecheck`：前端、服务端和测试类型检查通过。
- `npm test`：现有桌面回归、加密业务契约及发布配置检查通过，包含新增的纯中继/直连/切换契约组。v1 HTTP 回归夹具保存在 `test/legacy`，不进入生产构建，也不作为 v2 网络验收依据。
- `npm run test:browser`：15 项隔离 Chrome 移动视口检查通过；桌面为模拟夹具，网络为本机测试网络。
- `npm run test:cloud`：公网 6 项只读加密检查通过；最新 `test:public-browser` 的 8 项真实桌面只读浏览器检查通过。
- `test:frontend`、`test:layout`、`test:composer`：分别覆盖模块与计划交互、可见区域及恢复、移动导航与粘贴/运行中附件。使用模拟桌面与浏览器视口，不代表手机实测。
- `npm run test:storage`：实际配置的私有对象存储加密上传、下载及完整性检查通过。

同一附件两次打开时，第二次没有增加下载文件字节。直连附件阶段，中继 bulk 字节增量为 0，对象存储上传/下载计数均为 0。随后专门关闭直连测试 WSS 上传，因此整组浏览器测试最终中继 bulk 计数为 2,100,362 字节；不能把这个合计误解为直连阶段的流量。

存储测试中，电脑向存储上传了 2,097,184 字节密文（两个内容块供手机下载），从存储读取了 9,437,383 字节密文（手机上传供电脑导入）。指标方向相对于电脑 FileService，包含每块认证标签；不等于提供方账单用量。

未保留同一蜂窝网络下的 v1/v2 完整耗时和账单基线，因此不宣称公网延迟降低百分比。当前减负结论依据实际路径字节变化与缓存重读检查，而不是直连状态图标。

另外使用同一组合成 101 条记录比较重连协议正文，可用 `node --import tsx scripts/sync-benchmark.ts` 复现：

| 场景                           | v1 服务端应用 JSON 字节 | v2 服务端应用 JSON 字节 |
| ------------------------------ | ----------------------: | ----------------------: |
| 首次读取                       |                 226,560 |                 228,031 |
| 未变化时重新打开               |                 226,560 |                   1,866 |
| 一条消息末尾增加文字后重新打开 |                 226,569 |                     303 |

v2 恢复请求还携带 8,176 字节客户端版本清单。此对照使用 v1 的重连快照封装和实际 v2 SyncJournal 输出，统计未压缩应用 JSON，不包括 Noise、TLS、握手、静态资源或浏览器缓存开销，不是网络计费或耗时实测。

## 对象迁移验证边界

新版只签发密文附件授权，临时密文对象成功使用后清理。旧明文对象须按部署指南核对本机副本及哈希后再删除，不能批量假定已有备份。迁移清单含私有对象标识，应留在部署环境，不提交仓库。

存储提供方应配置 24 小时过期策略；授权过期不等于对象已删除。尚未通过持续一天的观测验证提供方实际删除的最迟时间。

## 尚未完成的实机验收

以下项目需要对应真实设备/网络，本次环境无法完成，未标记通过：

- Android Chrome 与 iOS Safari/PWA：后台挂起恢复、Wi-Fi/蜂窝切换、系统回收缓存、低配额以及媒体持续拖动。
- 不同 NAT/运营商下的连接耗时与打洞成功率、跨网络 IPv6、长时间 UDP 不可用与丢包；当前通过的是合成直连失败/WSS 回退和公网信令验证。
- Windows/macOS 的真实桌面 IPC、对端校验、权限、密钥存储与服务安装；首期交付接口边界及 Linux 实现。
- 真实桌面全功能交互的手机端回归，尤其审批、答题、队列与网络切换期间的结果确认。

真机测试应使用专用测试会话和合成附件。记录浏览器/系统版本、网络类型、直连/中继/存储字节、缓存命中、首次可交互时间、恢复耗时及重复执行计数，不记录正文或密钥。每个场景分别测冷启动与重复访问，避免将桌面本身的历史解析时间全部归因于网络。
